# P2.8 Analysis: Full CLI with Subcommands

## 1. Current State

`cli.py` contains a minimal CLI with a single `--model` argument. It
hardcodes one MCQ task, runs it through `run_single_test`, collects
Ollama usage, and prints via the legacy `print_report` function.

```python
# Current flow
main() → argparse(--model) → async_main(model)
  → construct hardcoded TestTask
  → get_yoker_config(), set model, validate
  → fetch_ollama_usage (before)
  → run_single_test(task, config)
  → fetch_ollama_usage (after)
  → print_report(task, result, before, after)
```

The public API `evaluate()` in `config.py` already encapsulates the full
suite-based flow: load suite → validate → create `EvalRunner` → run →
optionally compare baseline → return `TestReport`. The CLI does not use
this API yet — it still uses the single-task path.

**Key existing APIs available for the refactor:**

| API | Location | Purpose |
|-----|----------|---------|
| `evaluate(suite, model, compare, config, repeats)` | `config.py` | Full eval orchestration |
| `load_suite(path)` / `validate_suite(config)` | `loader.py` | Suite loading + validation |
| `_resolve_suite_path(suite)` | `config.py` | Resolve suite name → file path |
| `format_console_report(report)` | `report.py` | Format TestReport as text |
| `TestReport.to_yaml()` / `to_json()` | `schema.py` | Serialization |
| `TestReport.from_dict(data)` | `schema.py` | Deserialization (for baselines) |

**Existing tests** (`tests/test_cli.py`) test `async_main` and `main` with
the old single-task interface. These need full replacement for the new
subcommand-based interface.

**No `suites/` directory exists yet** (P2.9 creates the first suite). The
`suites` subcommand must handle an empty/missing directory gracefully.

## 2. Proposed Design

### Subcommand Structure

```
yoker-test eval --suite <name> [--model <model>] [--compare <path>] [--output <file>] [--repeats <n>]
yoker-test suites
yoker-test show --suite <name>
yoker-test --model <model>          # backward compat → eval --suite yoker_basic
```

### Backward Compatibility Approach

When no subcommand is given but `--model` is present (the old interface),
redirect to `eval` with a default suite of `yoker_basic`. This is handled
by checking `sys.argv` before argparse parsing: if the first positional
arg is not a known subcommand, inject `eval --suite yoker_basic` into the
argparse args.

A cleaner approach: use a custom argparse action or pre-parse `sys.argv`.
If `argv` contains no subcommand keyword (`eval`, `suites`, `show`) but
contains `--model`, construct the equivalent `eval` invocation. If neither
subcommand nor `--model` is given, print help.

### Subcommand Details

#### `eval`

```
yoker-test eval --suite <name> [--model <model>] [--compare <path>] [--output <file>] [--repeats <n>]
```

- `--suite` (required): suite name (resolves to `suites/<name>/suite.yaml`) or direct path
- `--model` (optional, default: `glm-5.2:cloud`): model to evaluate
- `--compare` (optional): path to baseline YAML/JSON for comparison
- `--output` (optional): file path to write serialized report (`.yaml` or `.json` extension determines format)
- `--repeats` (optional): override suite's default repeat count

**Flow:**
1. Call `evaluate(suite=..., model=..., compare=..., repeats=...)`
2. Print `format_console_report(report)` to stdout
3. If `--output` given, write `report.to_yaml()` or `report.to_json()` to file
4. Exit 0 on success, 1 on error (suite not found, validation failure, etc.)

#### `suites`

```
yoker-test suites
```

- Scan `suites/` directory for subdirectories containing `suite.yaml`
- Print a table: suite name, version, description, task count
- Handle missing/empty `suites/` directory with a helpful message

#### `show`

```
yoker-test show --suite <name>
```

- Load and validate the suite (without running)
- Print suite metadata: name, version, description, repeats, temperature, seed
- Print task summary: count by category, task IDs with difficulty
- Print aggregation weights if present
- Do not execute any tasks

### Step 4: Implement `cmd_eval`

```python
async def cmd_eval(suite, model, compare, output, repeats) -> int:
    try:
        report = await evaluate(
            suite=suite, model=model, compare=compare, repeats=repeats
        )
    except (FileNotFoundError, ValueError) as e:
        print(f"Error: {e}", file=sys.stderr)
        return 1

    print(format_console_report(report))

    if output:
        path = Path(output)
        if path.suffix == ".json":
            path.write_text(report.to_json())
        else:
            path.write_text(report.to_yaml())

    return 0
```

### Step 5: Implement `cmd_suites`

```python
def cmd_suites() -> int:
    suites_dir = Path("suites")
    if not suites_dir.is_dir():
        print("No suites/ directory found.")
        print("Create one with: mkdir -p suites/<name> && # add suite.yaml")
        return 0

    entries = sorted(suites_dir.iterdir())
    found = False
    for entry in entries:
        suite_file = entry / "suite.yaml"
        if entry.is_dir() and suite_file.exists():
            config = load_suite(suite_file)
            print(f"  {config.suite:<20} v{config.version:<8} {len(config.tasks)} tasks")
            print(f"    {config.description}")
            found = True

    if not found:
        print("No suites found in suites/ directory.")
    return 0
```

### Step 6: Implement `cmd_show`

```python
def cmd_show(suite) -> int:
    try:
        suite_path = _resolve_suite_path(suite)
        config = load_suite(suite_path)
    except (FileNotFoundError, ValueError) as e:
        print(f"Error: {e}", file=sys.stderr)
        return 1

    errors = validate_suite(config)
    if errors:
        print(f"Suite validation failed: {'; '.join(errors)}", file=sys.stderr)
        return 1

    # Print metadata
    print(f"Suite:        {config.suite}")
    print(f"Version:      {config.version}")
    print(f"Description:  {config.description}")
    print(f"Repeats:      {config.repeats}")
    print(f"Temperature:  {config.temperature}")
    print(f"Seed:         {config.seed}")
    if config.max_tokens:
        print(f"Max tokens:   {config.max_tokens}")

    # Print tasks grouped by category
    by_category: dict[str, list] = {}
    for task in config.tasks:
        by_category.setdefault(task.category, []).append(task)

    print(f"\nTasks ({len(config.tasks)} total):")
    for cat in sorted(by_category.keys()):
        tasks = by_category[cat]
        print(f"\n  [{cat}] ({len(tasks)} tasks)")
        for task in tasks:
            diff = f" ({task.difficulty})" if task.difficulty else ""
            scorer = task.scorer if isinstance(task.scorer, str) else "custom"
            print(f"    {task.id:<10}{diff:<12}scorer: {scorer}")

    # Print aggregation weights
    if config.aggregation_weights:
        print("\nAggregation weights:")
        for cat, weight in config.aggregation_weights.items():
            print(f"  {cat:<16} {weight}")

    return 0
```
